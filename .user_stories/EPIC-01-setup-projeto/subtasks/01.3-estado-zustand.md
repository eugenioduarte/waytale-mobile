# 01.3 — Estado com Zustand

Como dev, quero stores previsíveis e persistidas, para o estado sobreviver a reinícios.

## Passos

- [x] Instalar Zustand — `zustand@^5` em `apps/mobile`.
- [x] Stores em `src/stores/`: `session.store.ts`, `preferences.store.ts`, `journey.store.ts`
      (percurso ativo), `player.store.ts` (áudio) e `sync.store.ts` (fila e conectividade; só em
      memória, porque a outbox durável vive em SQLite, 01.4/01.6).
- [x] `persist` com AsyncStorage — `@react-native-async-storage/async-storage@2.2.0` (a versão
      que o Expo SDK 57 espera; a 3.x é uma reescrita nativa que o `expo install --check`
      rejeita). Escolhido em vez de MMKV porque funciona em Expo Go e no export web. A decisão
      está em `.agents_local/stack.md` › Estado (Zustand).
- [x] `partialize` para nunca persistir tokens em claro — `sessionStore` persiste uma whitelist
      (`isAuthenticated`, `hasCompletedOnboarding`, `user`); os tokens vão para SecureStore (01.5).
      `playerStore` também não persiste `isPlaying`, para um cold start nunca tocar sozinho.
- [x] Selectors memoizados — cada store expõe hooks granulares (`useIsAuthenticated()`, …) e
      `useXActions()` com `useShallow`. Consumir a store inteira (`useXStore()` sem selector) é
      erro de lint (`no-restricted-syntax` em `tooling/eslint/expo-app.js`); a regra também está
      documentada em `.agents_local/stack.md`.
- [x] Hidratação — `src/stores/hydration.ts` (`useStoresHydrated()`) espera que as quatro stores
      persistidas hidratem; o layout raiz mantém o splash até lá, para a guarda de rotas (01.2) não
      tratar um utilizador autenticado como anónimo no cold start.

## Aceitação

- [x] Matar a app durante um percurso e reabrir retoma paragem e posição do áudio — coberto por
      `src/stores/__tests__/persistence.test.ts`: persiste, limpa o estado em memória, hidrata e
      confirma `currentStopIndex` e `positionMs`. O mesmo ficheiro testa a whitelist da sessão.
      Falta confirmar num dispositivo quando houver ecrã de percurso e motor de áudio (épico
      journey).

## Dependências

- 01.1 (bootstrap) — precisa de `src/stores/`.
- `sessionStore` é consumido pela guarda de rotas de 01.2 e pela auth de 01.5 — alinhar o formato
  da sessão com o que 01.5 vai devolver do Supabase antes de fechar o schema do store.
