# 01.1 — Bootstrap do repositório

Como dev, quero um projeto Expo com TypeScript estrito e lint/format automáticos, para começar
sem discutir configuração.

## Passos

- [x] Monorepo pnpm workspaces + Turborepo (`pnpm-workspace.yaml`, `turbo.json`).
- [x] `create-expo-app` dentro de `apps/mobile`; `tsconfig` `strict: true` via
      `tooling/typescript`, paths `@/*`.
- [x] ESLint + Prettier partilhados via `tooling/eslint`/`tooling/prettier`.
- [x] Import/order enforcement — `import-x/order` via `eslint-plugin-import-x` (namespace próprio)
      em `tooling/eslint/base.js`. Conflito resolvido: `eslint-config-expo` já regista
      `eslint-plugin-import` como `import`, por isso re-declarar esse nome fazia o ESLint falhar
      com "Cannot redefine plugin". `import-x` aplica-se a todo o workspace (incluindo
      `packages/ui`, que não usa a config Expo), trata `@/*` como interno
      (`import-x/internal-regex`) e mantém o grupo `type` fora de propósito (type-imports seguem
      o grupo do caminho de origem). `base.js` declara `files: **/*.{js,jsx,ts,tsx}` e o parser
      `@typescript-eslint/parser` — sem isso o flat config só apanhava `*.js` e o lint de
      `packages/ui` passava sem analisar nenhum ficheiro TS.
- [x] Husky + lint-staged no pre-commit — `.husky/pre-commit` corre `pnpm exec lint-staged`
      (`pnpm --filter <pkg> exec eslint --fix` em `apps/mobile`/`packages/ui`; `prettier --write`
      em `{ts,tsx,js,jsx,json,md}`, o mesmo conjunto do `pnpm format`). O ESLint corre via
      `--filter` porque o lint-staged executa na raiz, que não tem `eslint.config.*`. Validado com
      um `.tsx` em stage. `"prepare": "husky"` na raiz liga os hooks no `pnpm install`.
- [x] `.gitattributes` com `* text=auto eol=lf`, para o `core.autocrlf` do Windows não fazer o
      `prettier --check` falhar por CRLF. `scripts/reset-project.js` do scaffold removido (apagaria
      a estrutura nova de `src/`).
- [x] Estrutura de pastas completa dentro de `apps/mobile/src/`: `features/<dom>/`
      (`features/auth/`), `db/`, `lib/`, `stores/`, `i18n/` — a par de `app/`, `components/`,
      `constants/` e `hooks/` do scaffold.
- [x] `tests/` e `.maestro/` em `apps/mobile/` (criados com `.gitkeep`; conteúdo entra em 01.8).

## Aceitação

- [x] `pnpm --filter mobile web` gera bundle sem erros — validado com
      `expo export --platform all`: Android 2.7MB, iOS 2.4MB, web 1.2MB e 16 rotas estáticas
      (revalidado com o layout `(auth)`/`(tabs)`).
- [ ] `pnpm --filter mobile ios` e `pnpm --filter mobile android` arrancam — os bundles das duas

- [x] `pnpm test` passa — `apps/mobile` e `packages/ui` correm `jest --passWithNoTests` (ainda não

- [ ] Tudo o que precede corre em CI (depende de 01.13).

## Notas

- `pnpm install` corre com `node-linker=hoisted`; se aparecer
  `ERR_PNPM_ENOENT ... '<pkg>_tmp_<pid>'`, apagar `node_modules` e reinstalar resolve (limitação
  do linker hoisted em Windows, não do repositório).
- `expo export` avisa `Could not parse Expo config: android.googleServicesFile` porque
  `google-services.json` é local e ignorado pelo git — ver 01.12.
- O `test` de `turbo.json` declara `outputs: ["coverage/**"]` e o turbo avisa que não existem
  ficheiros de output enquanto o `test:cov` (01.8) não existir.
- O pre-commit formata exatamente os mesmos tipos que o `pnpm format`
  (`{ts,tsx,js,jsx,json,md}`); `*.yaml`/`*.yml` ficam de fora (e o `pnpm-lock.yaml` fica fora do
  Prettier para não entrar em conflito com o que o pnpm escreve).
- Prettier: o corpus de docs ainda não está normalizado (202 `*.md` + 28 yaml falham o
  `prettier --check` hoje), portanto cada doc é normalizado quando for tocado — foi o que
  aconteceu a `.agents_local/stack.md` (alinhamento da tabela). Um `pnpm format` global continua a
  ser uma decisão separada, fora de 01.1.
