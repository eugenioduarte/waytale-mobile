Como dev, quero um cliente HTTP e mocks locais previsíveis, para desenvolver sem depender do
backend estar sempre disponível.

## Passos

- [x] Instalar Axios; instância única com interceptors de auth e erro em `src/lib/http.ts`
      (nunca `fetch` direto em features).
  - `getHttp()` tem base `<EXPO_PUBLIC_SUPABASE_URL>/functions/v1` (Edge Functions).
  - Interceptor de auth: `apikey` e o JWT do utilizador quando há sessão.
  - Interceptor de erro: `HttpError` com `kind` (network, timeout, unauthorized, client, server) e
    `retryable`.
  - O ESLint proíbe `fetch`, `XMLHttpRequest` e `import axios` fora de `src/lib/http.ts`.
- [x] Instalar `mockoon-cli` (o environment `tooling/mockoon/waytale.json` já existe, com 2 rotas
      placeholder — `mockoon-cli` ainda não está instalado, o script `pnpm mockoon` na raiz
      falhará até lá).
  - Instalados `@mockoon/cli` e `@mockoon/commons-server` 9.9.0. `pnpm mockoon` funciona.
  - O environment passou a imitar os caminhos do Supabase: Auth (`otp`, `verify`, `token`,
    `user`, `logout`), PostgREST (`/rest/v1/:table` para o sync) e a Edge Function
    `generate-route`. As 2 rotas placeholder saíram.
  - **Dados mock centralizados** em `tooling/mockoon/`:
    - `data/` tem as respostas por ficheiro: o catálogo de demonstração no formato de linha do
      Supabase, a sessão e a Edge Function.
    - `scenarios.json` tem os inputs que escolhem cada erro. `server.test.js` verifica que batem
      com as regras.
  - **Os testes usam o Mockoon** através de `startMockServer()` (`@tests/mockoon`): um processo
    Node por ficheiro, numa porta livre, com o motor real e o mesmo JSON do dev.
  - O teste de Auth passou do MSW para o Mockoon, com os mesmos 9 cenários. Há testes novos para o
    HTTP e para o pull do sync contra o mock.
  - O MSW e `tests/msw/` saíram.
  - O seed de demonstração (`src/db/seed.ts`) lê as mesmas linhas de `data/rest/`.
- [x] Instalar `date-fns`; toda a manipulação/formatação de datas centralizada em
      `src/lib/date.ts`.
  - O relógio: `now`, `nowIso`, `nowMs`.
  - ISO: `parseIso`, `shiftIso`, `isAfterIso`.
  - Formatação por idioma, com os locales pt, en-GB e es: `formatDuration`, `formatRelative`,
    `formatDate`.
  - Os `new Date()`/`Date.parse` do sync, do outbox e dos guardados passaram para ele.

## Aceitação

- [x] A app corre contra o Mockoon só trocando uma env var, sem tocar em código de produção.
  - Basta `EXPO_PUBLIC_SUPABASE_URL=http://localhost:3001` (o mock aceita qualquer chave
    publicável). O Auth, o sync e o HTTP vão juntos para o mock.
  - Atalho: `pnpm mockoon` + `pnpm --filter mobile start:mock`.
  - No emulador Android usa-se `10.0.2.2:3001`.
- [x] Nenhuma função de data usa `Date`/`Intl` diretamente fora de `src/lib/date.ts`.
  - O ESLint (`no-restricted-syntax`) rejeita `new Date`, `Date.*`, `Intl.*` e `toLocale*String`
    fora dele.
  - O `pnpm lint` passa, e já apanhou um `Date.parse` no pull do sync.
  - Testes e scripts ficam de fora da regra.
