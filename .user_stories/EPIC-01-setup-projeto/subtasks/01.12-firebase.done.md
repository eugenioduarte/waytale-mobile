## Passos

- [x] Definir o package name Android: `com.waytale.app` (`apps/mobile/app.json` ›
      `expo.android.package`) — é o mesmo valor a usar ao registar a app Android no Firebase.
- [x] Criar o projeto Firebase do Waytale (`waytale-36b9f`) e registar a app Android com o
      package `com.waytale.app`.
- [x] `google-services.json` colocado em `apps/mobile/google-services.json` (gitignored — não
      commitar o ficheiro real) e referenciado em `app.json` › `expo.android.googleServicesFile`.
  - Passou a ser referenciado pelo `app.config.js`, que também aceita a env var de ficheiro do EAS
    (`GOOGLE_SERVICES_JSON`).
  - O `bundleIdentifier` iOS é `com.waytale.app`.
- [x] Instalar `@react-native-firebase/app` + `crashlytics` + `messaging` + `analytics`.
  - Versão 26.4, com os config plugins, e `expo-build-properties` (iOS `useFrameworks: static`).
  - O `firebase.json` desliga a recolha por omissão e não usa IDs de publicidade.
  - O código da app usa só `@/lib/firebase`: carrega o RNFB de forma preguiçosa e nunca lança
    erro. Sem módulo nativo (Jest, Expo Go) tudo é no-op. O web tem um no-op próprio.
  - **Consentimento:** interruptor no Perfil (`profile-data-collection`, pt/en/es). O
    `useFirebase()` aplica-o e ainda liga o id Supabase pseudónimo e os screen views por rota.
  - **Crash de teste:** botão só em dev no Perfil (`profile-test-crash`).
- [x] Confirmar dev client (não Expo Go) — já assumido nos Riscos do épico por causa de
      áudio/localização em background; Firebase reforça a mesma exigência.
  - Instalado o `expo-dev-client`. Os scripts `pnpm android`/`ios` passaram a `expo run:*`.
  - `android/` e `ios/` são geradas (CNG) e estão no `.gitignore`.
- [x] Registar token FCM no Supabase por utilizador (depende de 01.5).
  - **Tabela:** `public.push_tokens` (token, user_id, platform), com RLS: cada um lê e apaga só
    os seus tokens.
  - **Registo:** através da função `register_push_token` (`security definer`), que passa o token
    ao utilizador atual quando outra pessoa entra no mesmo telemóvel.
  - **Na app:**
    - a permissão pede-se no passo "Permissões" do onboarding;
    - o token regista-se no arranque, ao entrar e quando roda, e sai ao terminar sessão;
    - uma falha vai para o Crashlytics, sem bloquear nada.
  - **Testes:** RLS no PGlite; o registo contra o Mockoon, com rotas novas `rpc/:fn` e `DELETE`.
  - **Ícone de notificação:** o plugin local `plugins/with-notification-icon.js` cria-o, porque o
    Expo 57 já não o faz. O ícone ainda é o do template.
- [x] Eventos mínimos de analytics: `route_started`, `story_played`, `journey_completed`,
      `place_saved`.
  - São tipados em `src/lib/firebase/events.ts`, sem dados pessoais.
  - Disparam onde a ação acontece: `route_started` e `journey_completed` (com a duração) na store
    da jornada, `story_played` na store do player, e `place_saved` em `saveItem`.

## Aceitação

Adiada, por decisão do utilizador, para os testes com UI: validar num telemóvel Android com um
build de desenvolvimento. Todos precisam de `apps/mobile/google-services.json`.

- [ ] Um crash forçado em dev aparece no Crashlytics em minutos.
  - `pnpm --filter mobile android`, depois Perfil › "Testar relatório de falha".
  - A seguir, reabrir a app: o relatório é enviado no arranque seguinte.
- [ ] Um evento de analytics fica visível no dashboard Firebase.
  - Correr `adb shell setprop debug.firebase.analytics.app com.waytale.app` e ver em
    Analytics › DebugView (screen views e eventos).
  - Os eventos de produto aparecem quando as ações existirem nos ecrãs (EPIC-09 a 16). Hoje o
    screen view já chega.
- [ ] Uma notificação de teste chega ao dispositivo.
  - Aceitar as notificações no onboarding e copiar o token `[push] FCM token:` dos logs do Metro.
  - Enviá-lo em Firebase › Messaging › "Send test message", com a app em background.
