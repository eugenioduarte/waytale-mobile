## Passos

- [x] Instalar Storybook RN no dev client de `apps/mobile` — `@storybook/react-native` 10.6 com
      os addons on-device de controls e actions. Configuração em `apps/mobile/.rnstorybook/`,
      rota `/storybook` (`src/app/storybook.tsx`). `pnpm --filter mobile storybook` arranca a app
      com `EXPO_PUBLIC_STORYBOOK_ENABLED=true`; depois abre-se `waytale://storybook`. Sem a flag, o
      `withStorybook` do `metro.config.js` troca o Storybook por módulos vazios e a rota
      redireciona para a Home. Corre também no Expo Go: não há nenhum módulo nativo fora do Expo
      Go.
- [x] Build web do Storybook publicado em preview por PR — `@storybook/react-native-web-vite`
      (`apps/mobile/.storybook/`, as mesmas histórias via react-native-web).
      `pnpm --filter mobile storybook:web` para desenvolvimento, `storybook:build` para o build
      estático. `.github/workflows/storybook-preview.yml`: nos PRs que tocam em
      `apps/mobile/src`, `packages/ui` ou na configuração do Storybook, corre os testes das
      histórias, faz o build, publica em `gh-pages/pr-<n>/` e comenta o link no PR (o comentário é
      atualizado a cada push). Fechar o PR apaga o preview. PRs de forks não publicam (o token é
      só de leitura).
- [x] Decorators com tokens, safe-area e mocks de store — `src/storybook/decorators.tsx`,
      partilhados pelas duas configurações:
  - **tokens:** o fundo e o espaçamento da app à volta de cada história (`layout: 'fullscreen'`
    desliga isto);
  - **safe-area:** `SafeAreaProvider` com insets fixos de um iPhone, para a web e o dispositivo
    darem o mesmo resultado;
  - **mocks de store:** `parameters.stores` (`sync`, `session`); cada história começa das stores no
    estado inicial, sem herdar nada da anterior.

## Notas

- **Primeiro run falhou no CI (corrigido):** o `composeStories` carrega o `storybook/test`, cujo
  user-event regista um `afterEach` que lê `window.navigator.clipboard`. No Jest de React Native
  o `window` é o objeto global, que só tem `navigator` a partir do Node 21, e o CI usa o Node 20
  do `.nvmrc`. O teste das histórias cria um `navigator` vazio quando não existe; testado em Node
  20.19.0 e 24.
- **Testes de SQLite no CI:** os testes com `node:sqlite` (01.4, 01.6) ficam em `describe.skip` no
  Node 20. Não afetam este workflow (ele só corre os testes das histórias), mas o CI geral (01.13)
  deve usar Node 22.5+ ou o `.nvmrc` deve subir.

- **`react-native-safe-area-context`:** o `@storybook/react-native` 10.6 pede exatamente 5.8.0 e o
  Expo SDK 57 fixa ~5.7.0. Ficou a versão do Expo (é a que está no binário nativo). O único
  sintoma é um aviso de peer dependency.
- **Jest e ESM:** o Storybook 10 só publica ESM. `apps/mobile/jest.config.js` passa a
  transformar `storybook` e `@storybook/*` para os testes das histórias.
- **`@react-native-community/datetimepicker`, `slider` e `@gorhom/bottom-sheet`** são peers dos
  addons on-device; o `expo install` acrescentou o config plugin do datetimepicker ao `app.json`.
- **`.rnstorybook/storybook.requires.ts`** é gerado pelo Metro quando o Storybook está ligado
  (ou por `pnpm --filter mobile storybook:generate`). Está no repo para o typecheck, e fica fora
  do lint.
