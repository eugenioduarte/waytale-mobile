Como utilizador, quero que a app funcione sem rede, porque ando na rua e no estrangeiro.

## Passos

- [x] Instalar `expo-sqlite@~57.0.3` + `drizzle-orm@0.45` (+ `drizzle-kit` como devDependency).
- [x] Tabelas: `routes`, `stops`, `stories`, `story_audio`, `places`, `saved_items`, `journeys`,
      `journey_events`, `downloads`, `outbox`, `meta` — `src/db/schema.ts` (11 tabelas).
      `saved_items` e `downloads` têm índice único `(user_id, item_type, item_id)`, para guardar
      duas vezes ou repetir um sync não duplicar linhas.
- [x] Migrações Drizzle versionadas — `drizzle-kit generate` produz `.sql` + `_journal.json`;
      `scripts/bundle-migrations.mjs` empacota-as em `src/db/migrations/index.ts` (o Metro não
      importa `.sql`). `pnpm db:generate` = `drizzle-kit generate && node scripts/bundle-migrations.mjs`.
      As chaves são `m0000`, `m0001`, … porque é assim que o migrator do `expo-sqlite` as procura;
      com a tag como chave, `migrate()` falhava com "Missing migration" em todos os arranques.
- [x] Seed de demonstração — `src/db/seed.ts` (rota "Baixa de Lisboa", 2 paragens, 2 histórias,
      áudio); idempotente (`onConflictDoNothing`), corre no arranque só em `__DEV__`.
- [x] Offline-first — `src/db/client.ts` (`getDatabase`/`migrateDatabase`) é a única porta de
      leitura da UI; a rede nunca alimenta a UI diretamente (regra em `.agents_local/stack.md`).
      Cada ligação liga `PRAGMA foreign_keys` (sem isso os `onDelete: cascade` são ignorados) e
      WAL. O layout raiz mantém o splash até `useDatabaseReady()`, para nenhum ecrã ler uma tabela
      que ainda não existe; se a inicialização falhar, o erro é registado e a app continua.

## Dependências

- 01.1 (bootstrap) — `src/db/` criado.
- O schema das tabelas de utilizador (`saved_items`, `journeys`, `journey_events`, `downloads`,
  `outbox`) está alinhado com Postgres (01.5): `user_id` = `auth.uid()`, uuid-as-text e timestamps
  ISO-8601 — para 01.6 espelhar os campos 1:1.

## Notas

- `expo-sqlite` no web usa wa-sqlite (`.wasm`) — `metro.config.js` adiciona `wasm` a `assetExts`.
- `src/db/migrations/index.ts` é gerado (`pnpm db:generate`) e commitado, para um clone limpo
  typecheckar/exportar sem build step.
- O teste de migrações usa `node:sqlite` (Node 22.5+) e é saltado em Nodes mais antigos; o
  `engines` da raiz ainda aceita `>=20.19`.
